# File safety and architecture

React owns selection, filters, form state, and drafts. Rust owns registered imported paths, metadata parsing, conflict hashes, and writes. The frontend cannot save an unregistered arbitrary path. All metadata work runs on blocking workers, outside Tauri's UI event loop, under a serialized library mutex. Import progress emits every 20 files. Frontend batch saves are sequential with per-file status.

Writes clone the entire original into a same-directory temporary file. Lofty updates the existing primary tag, retaining unrelated supported tag items and other tag blocks. No audio encoder is part of TagForge. The staged file is parsed again; edited fields and artwork must match. The original's SHA-256 must still match its imported fingerprint. An exclusive-create recovery copy is flushed before replacement.

Windows metadata-only saves use ReplaceFileW to replace the original with the staged file. Renames publish using a no-clobber hard link, then remove the old name; failures leave the original in place where possible. Renaming requires hard-link support (normally NTFS). Filesystems without it are refused rather than falling back to overwrite. A crash between publication and source removal can leave two names, preserving recoverable data. A batch is not an all-files atomic transaction.

Undo verifies both saved bytes and backup bytes before restoration. Permanent backups are retained by default. If retention is disabled, application-owned temporary rollback copies are cleaned up at normal exit when possible; crashes or locked files may leave them for recovery. Existing destination paths, path separators, Windows reserved device names, extension changes, and stale edits are refused. Damaged files become individual import errors. Folder traversal does not follow directory symlinks.

Limitations: filesystem permissions, ACLs, timestamps, alternate data streams, and file IDs may behave differently on replacement and require manual verification; do not promise their preservation. Lofty's preservation of proprietary or malformed tag structures is not guaranteed. Multi-valued fields edited through this single-value UI are intentionally replaced by one value. Other fields remain as represented by Lofty, which is not a byte-for-byte guarantee for rewritten metadata blocks. Keep backups.

Fingerprint checking narrows but does not eliminate the race with another process writing after the final check. This release does not hold exclusive filesystem locks across replacement or maintain a durable transaction journal. Network shares and concurrently modified libraries require further validation before claiming production reliability. Recovery copies mitigate failures but do not replace an independent music backup.
